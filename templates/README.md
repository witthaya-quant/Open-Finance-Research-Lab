# OFRL Project Templates

Use these templates to create a project baseline. Every project must follow [PROJECT_LIFECYCLE.md](../PROJECT_LIFECYCLE.md) and [PROJECT_STANDARDS.md](../PROJECT_STANDARDS.md). Select documents by project type and risk tier; do not copy documents that do not apply to the work.

## Universal project documents

| Template | Use |
|---|---|
| [Project README](PROJECT_README_TEMPLATE.md) | Project landing page, scope, status, limitations, and navigation |
| [Project Charter](PROJECT_CHARTER_TEMPLATE.md) | Project-level problem, objectives, scope, risks, and deliverables; use separately or integrate into the main specification |
| [Project Manifest](PROJECT_MANIFEST_TEMPLATE.json) | Machine-readable identity, lifecycle, type, risk, licence, and validation metadata |
| [Project Decision Log](PROJECT_DECISION_LOG_TEMPLATE.md) | Project-level decisions, open questions, deferred scope, and accepted limitations |
| [Validation Matrix](VALIDATION_MATRIX_TEMPLATE.md) | Acceptance criteria, test evidence, PASS / FAIL / NOT RUN / BLOCKED / N/A state |

## Research and quantitative work

| Template | Use |
|---|---|
| [Research Specification](RESEARCH_SPECIFICATION_TEMPLATE.md) | Research question, prior work, method, data, experimental design, results, and limitations |
| [Research Project Template](RESEARCH_PROJECT_TEMPLATE.md) | Detailed research project planning and reporting format |
| [Data Manifest](DATA_MANIFEST_TEMPLATE.md) | Provenance, data rights, classification, transformations, quality, and integrity |
| [Benchmark Specification](BENCHMARK_SPECIFICATION_TEMPLATE.md) | Benchmark corpus, oracle, baselines, metrics, leakage controls, and reproducibility |

## Financial models

| Template | Use |
|---|---|
| [Model Conventions](MODEL_CONVENTIONS_TEMPLATE.md) | Units, currencies, periods, signs, accounting/domain basis, variables, and calculation rules |
| [Numeric Envelope](NUMERIC_ENVELOPE_TEMPLATE.md) | Numeric representation, range/scale, rounding, overflow, and accumulated-error budget |

## Software and infrastructure

| Template | Use |
|---|---|
| [Engineering Architecture](ENGINEERING_ARCHITECTURE_TEMPLATE.md) | Components, contracts, data flows, interfaces, failure behavior, deployment, and trade-offs |
| [Threat Model](THREAT_MODEL_TEMPLATE.md) | Assets, actors, trust boundaries, abuse cases, controls, and residual risk |
| [Prototype Plan](PROTOTYPE_PLAN_TEMPLATE.md) | Bounded feasibility question, hypothesis, tests, timebox, and promotion/stop criteria |

## Release and publication

| Template | Use |
|---|---|
| [Release Record](RELEASE_RECORD_TEMPLATE.md) | Release provenance, validation, SBOM, checksums, licence, and authorization; complete when an artifact is actually released |

## Governance and research proposals

| Template | Use |
|---|---|
| [Research Proposal](RESEARCH_PROPOSAL_TEMPLATE.md) | Propose a new research question or project direction |
| [Decision Record](DECISION_RECORD_TEMPLATE.md) | Record material lab-wide or cross-project decisions |

Templates are starting points. The project manifest and the applicable standards define the required documents. A template does not by itself establish that a project has passed review or validation.
