## 1. Context

Describe the problem, the situation that requires a decision, and why a decision is needed now. Separate verified facts from assumptions and open questions.

## 2. Decision drivers

List the criteria that matter. Examples include correctness, evidence quality, reproducibility, performance, numerical precision, security, data rights, compatibility, maintenance burden, cost, and practical usefulness.

## 3. Options considered

Include credible alternatives and the option to defer or do nothing where relevant.

| Option | Description | Advantages | Disadvantages / risks |
|---|---|---|---|
| A | | | |
| B | | | |
| Defer / no change | | | |

## 4. Decision

State the selected option precisely. Define its scope, conditions, effective version, and anything that is explicitly not included.

## 5. Rationale

Explain why this option best meets the decision drivers. State which evidence supports the decision and which parts rely on judgement or assumptions.

## 6. Consequences and trade-offs

Record positive consequences, negative consequences, costs, constraints, compatibility impacts, risks, and follow-up work. Do not describe a trade-off as eliminated if it has only been moved elsewhere.

## 7. Validation and acceptance criteria

| Validation item | Required evidence / pass criterion | Result | Reference |
|---|---|---|---|
| | | Pending | |

State what is proven, what is not yet implemented, and what remains open. An accepted decision does not mean its implementation has passed validation.

## 8. Conflicts of interest and attribution

Record relevant interests, disclosures, recusals, external sources, and substantive contributor roles. Write "None identified" only when the matter has been considered.

## 9. Revisit conditions

Identify events or evidence that should cause this decision to be reconsidered, such as a changed research objective, new data, failed validation, new regulation, security finding, changed dependency, or material operational constraint.
