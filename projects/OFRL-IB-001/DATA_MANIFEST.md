## 1. Purpose and intended use

Case A is the deterministic synthetic reference dataset used to exercise the Integrated Three-Statement Financial Model's input contract and historical accounting checks. It describes a fictional non-financial operating company. It is not a real issuer, market observation, forecast expectation, or statistically representative sample.

The dataset supports structural schema validation, typed input parsing, historical statement-consistency checks, and future calculation-engine tests. It does not establish forecast-engine correctness or model-level financial validity.

## 3. Classification and privacy

The dataset is synthetic and describes one fictional generic non-financial operating company. It contains no intended personal, client, employer, confidential, or restricted information. The scenario is not generated by perturbing or transforming an underlying real-company dataset.

## 5. Collection or generation method

The values are explicitly specified as a deterministic reference case and stored in version-controlled documentation and a canonical JSON fixture. No external API, vendor feed, issuer filing, or paid dataset is used. There is no random seed because the fixture is not generated through a random sampling process.

## 6. Transformations and exclusions

No source-data extraction, joins, corporate-action adjustments, market-data transformations, or issuer normalization are performed. Model inputs are represented as decimal strings in JSON. The case deliberately excludes complex entity structures and accounting treatments outside the V1 model scope.

## 7. Quality controls

Current controls include:

- Draft 2020-12 JSON Schema validation of the canonical fixture.
- Rust typed parsing and the documented historical semantic checks.
- CI execution of the input-schema and Rust validator test suites.

These controls establish input-contract and implemented historical-validation behavior only. They do not validate forecast calculations, Scenario Feasibility, an analyst-facing XLSX export, or statistical representativeness; those capabilities remain unimplemented or outside scope.

## 8. Integrity and versioning

The dataset is versioned as 0.1.0 through its fixture filename and schema reference. A material change to field structure requires an input-schema version review; a change to case values or assumptions requires a documented fixture/reference-case revision and corresponding tests. A release checksum will be recorded if the dataset is packaged as a release artifact.

## 9. Limitations and known risks

- The dataset is a single synthetic example and cannot support empirical or market-wide inference.
- Historical periods are synthetic inputs, not reported financial statements.
- Forecast assumptions are illustrative inputs; no forecast calculation engine currently produces forecast outputs.
- The case intentionally simplifies debt, tax, working capital, and PP&E mechanics as documented in the project specification.
- Passing input validation does not establish the economic plausibility of assumptions or correctness of the future model engine.
